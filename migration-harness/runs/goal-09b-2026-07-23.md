## 구현 계약

### Single sink와 startup

- `GAME_EVENT_STORAGE`는 `jsonl|postgres`만 허용한다. local/test 생략은 JSONL이고 production 생략·unknown은 HTTP listen 전에 실패한다.
- PostgreSQL mode는 `DATABASE_URL`과 migration history의 최신 version `2`를 확인한 뒤에만 listen한다. raw URL, password와 driver error는 외부 오류나 로그에 남기지 않는다.
- PostgreSQL mode에서는 JSONL repository/file을 open·append하지 않고 장애 시 JSONL fallback이나 dual-write도 하지 않는다.
- 기존 Docker CI, source-less release application, production HTTP integration과 Playwright production server는 `GAME_EVENT_STORAGE=jsonl`을 명시한다.

### Identity, receipt와 projection

- match 생성 시 `crypto.randomUUID()` game ID를 한 번 만들고 game start, human/AI placement와 game over가 공유한다.
- human placement는 active session room/player와 30초 TTL·player당 최대 128개의 authoritative `(clientSequence, pieceIndex)` receipt로 인증한다. client의 game/room/player identity는 저장 identity로 사용하지 않는다.
- lifecycle/heuristic AI는 `server_authoritative`, human placement는 `client_reported`다.
- projector는 event별 top-level/nested allowlist로 새 `CanonicalGameEvent`를 만들며 nickname, token, socket ID, IP, Cookie, User-Agent, DB URL/credential과 자유형 사용자 문자열을 복사하지 않는다.
- game over schema v2 payload는 player별 expected placement count와 receipt policy metadata를 보존한다. incomplete game의 export 제외는 Goal 9C 범위다.

### Migration과 저장

- 기존 `001_game_events.sql`은 바꾸지 않았다.
- `002_lifecycle_event_v2.sql`은 lifecycle schema v1과 v2를 함께 허용해 기존 row 조회를 보존한다. placement와 identity-v1 제약, partial unique index와 append-only 정책은 그대로다.
- repository는 inserted/duplicate/conflict를 유지한다. runtime retry 분류는 `ECONNREFUSED`, `ECONNRESET`, `ETIMEDOUT`, SQLSTATE `08*`, `40001`, `40P01`과 pg의 고정 timeout message만 transient로 취급한다.
- validation, constraint와 `IDEMPOTENCY_CONFLICT`는 재시도하지 않는다. 같은 immutable snapshot으로 최대 3회, 전체 2.7초 budget을 사용한다.
- pool 최대 4, direct in-flight 최대 16이며 대기 queue를 만들지 않는다. 실패는 safe code, event type과 attempt count 및 counter로 관찰하고 gameplay를 rollback하지 않는다.

### Shutdown

종료 순서는 다음으로 고정했다.

```text
신규 DB write 차단
→ Socket handler/ticker event 생산자 정지
→ 기존 in-flight write 최대 3초 drain
→ PostgreSQL pool close
→ Socket.IO/HTTP close
→ 전체 8초 hard deadline
```

shutdown과 repository close는 idempotent하다. producer disposer 이후 기존 socket도 새 game event를 생산하지 않으며 두 번째 shutdown 호출은 같은 Promise를 반환한다.

## 남은 위험과 미검증 범위

- production PostgreSQL provider, managed credential/CA와 external TLS/reverse proxy는 선택하거나 검증하지 않았다.
- branch 변경의 hosted CI는 push 전이므로 실행하지 않았다. hosted PostgreSQL CI service는 Goal 9D 범위다.
- process crash와 최종 retry 실패의 개별 event 유실은 승인된 best-effort 한계다.
- multi-instance ordering, durable outbox, automated retention/size alert와 기존 JSONL backfill은 구현하지 않았다.
- production mode는 활성화하지 않았고 JSONL이 계속 기본 runtime sink다.

## Rollback

1. production 환경이 존재한다면 먼저 `GAME_EVENT_STORAGE=jsonl`을 명시한다. mode 삭제는 rollback이 아니라 production startup failure다.
2. 문서, test, shutdown, runtime storage, canonical projection commit 순서로 Goal 9B commit을 역순 revert한다.
3. `001`/`002` migration으로 생성되거나 저장된 PostgreSQL table과 row는 자동 삭제하지 않는다.
4. down migration, DB/volume/data 삭제는 별도 사용자 승인 없이는 수행하지 않는다.

이 기록은 local merge gate까지의 결과다. push, main merge, production PostgreSQL 활성화와 Goal 9C는 별도 승인 전 수행하지 않는다.
