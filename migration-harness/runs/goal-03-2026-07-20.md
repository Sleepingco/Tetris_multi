## Event 계약 inventory

### Handshake

- strict auth object: `nickname`, optional `playerId`, `token`, `credentialError`
- 기존 신규 발급, partial/malformed/invalid credential, resume와 token rotation 의미는 Goal 2 그대로 유지한다.
- 처리 순서: origin/transport size → IP rate limit → strict auth parse → session authenticate

### Client → server 12개

| 그룹 | event |
| --- | --- |
| chat | `global:chat`, `room:chat` |
| room lifecycle | `room:create`, `room:join`, `room:leave`, `room:start`, `room:sync` |
| game | `game:join`, `game:input`, `game:bag:request`, `game:log:placement_decision`, `game:leave` |

일반 app event 처리 순서는 active socket/session generation → server-derived player rate bucket → Zod parse → room membership/host/status authorization → pending input/sequence queue → service/domain 호출이다. stale/replaced socket은 parse나 rate bucket을 사용하기 전에 `NOT_AUTHORIZED`로 끝난다.

### Server → client 16개

| 그룹 | event |
| --- | --- |
| session/chat | `session:ready`, `chat:result`, `global:message`, `room:message` |
| room | `room:result`, `room:updated` |
| game result | `game:join:result`, `game:input:result`, `game:log:result`, `game:bag:result`, `game:leave:result` |
| game broadcast | `game:bag:append`, `game:opponent-left`, `game:authoritative:snapshot`, `match:finish`, `pve:ai-policy` |

모든 browser application listener는 `roomClient`의 한 S2C validation 경계를 통과한다. `logClient`의 raw connection 구독을 제거하고 검증된 `game:log:result` adapter를 사용한다.

## Runtime validation 정책

- production `safeParse`는 server의 handshake/C2S 수신과 browser의 S2C 수신에서 한 번만 수행한다.
- client outbound와 server outbound에는 runtime parse wrapper를 추가하지 않았다. 대신 실제 fake socket/server emission을 event schema에 대조한다.
- handshake, 작은 control envelope, transform, board, room DTO와 고정 nested object는 unknown key를 거부한다.
- human playerId는 UUID v4, AI playerId는 `heuristic-ai-${roomId}`, roomId는 8자리 uppercase hex로 분리했다.
- human nickname은 trim 후 1~24자, chat은 trim 후 1~200자다.
- public AI nickname은 기존 `Heuristic AI`와 `My Imitation AI (Experimental)`만 허용한다.
- board는 20×10이고 기존 7개 tetromino와 server garbage 적용 결과인 `garbage` cell을 허용한다. active piece, hold와 piece queue에는 `garbage`를 허용하지 않는다.
- action, rotation, phase, room/match status, AI policy/difficulty는 현재 runtime enum으로 제한한다.
- 안전한 정수, 음수 허용 필드, row/col과 score 범위를 event 의미에 맞춰 분리했다.
- bagChunks와 pieceQueue에는 장시간 정상 gameplay를 막는 schema-only 개수 상한을 추가하지 않았다.

invalid payload는 새 error event 없이 기존 result channel에서 다음 안정적인 이유만 반환한다.

```json
{
  "ok": false,
  "reason": "INVALID_PAYLOAD"
}
```

raw payload, token, unknown key 이름, Zod issue와 stack은 response나 production log에 포함하지 않는다. `game:input` invalid result는 안전한 정수로 확인된 기존 `clientSequence`와 `pieceIndex`만 선택적으로 보존한다.

## Placement log와 bag 경계

- placement 외부 envelope `{roomId, log}`는 strict 처리한다.
- log 본문은 Zod로 기존 versioned domain schema를 복제하지 않는다.
- 기존 256 KiB 제한과 recursive private-field scan을 유지한다.
- human schemaVersion 1/2와 source 조건을 확인한 뒤 roomId/playerId를 인증된 socket session 값으로 덮어쓴다.
- 기존 `validatePlacementDecisionLog`를 저장 전 domain validation으로 계속 사용해 type/x/y와 versioned 확장 필드를 보존한다.
- save 직전 active socket/generation 재검사를 유지하며 stale async request는 side effect를 만들지 않는다.

`game:bag:request`는 기존 `ensurePlayerBagQueue()`를 사용한다.

- authoritative queue가 충분하면 state를 늘리지 않고 `BAG_QUEUE_SUFFICIENT`를 반환한다.
- browser는 해당 result에서 pending request를 해제한다.
- low-water일 때만 정확히 7개 bag chunk를 room에 broadcast한다.
- 충분한 queue의 반복 요청이 state를 증가시키지 않는 integration test와 pending 해제 후 재요청 가능한 client test를 추가했다.

## Client inbound failure

- invalid S2C는 application handler를 호출하지 않는다.
- browser warning에는 event 이름과 `INVALID_SERVER_PAYLOAD` protocol code만 남기고 payload를 출력하지 않는다.
- invalid `session:ready`는 active session으로 기록하지 않고 terminal `SESSION_PROTOCOL_ERROR`로 연결을 중단한다.
- stale page의 credential/sessionStorage는 삭제하지 않는다.
- 정상 session ready, reload/reconnect, sendBuffer 정리와 terminal disconnect 계약은 Goal 2 동작을 유지한다.

## 남은 위험과 미실행 범위

- strict schema에 현재 테스트가 포착하지 못한 정상 result variant가 있으면 해당 S2C가 browser handler 전에 차단될 수 있다. event별 actual emission parity와 전체 E2E를 추가했지만 모든 장시간 상태 조합을 열거한 것은 아니다.
- client bundle gzip이 19.19 kB 증가했다.
- malformed payload는 512 KiB transport 상한과 event별 rate bucket을 공유한다. 장시간/분산 fuzz와 abuse soak는 수행하지 않았다.
- local Chromium과 loopback HTTP만 검증했다. WebKit/Firefox, 외부 TLS termination, reverse proxy와 cross-region network는 미실행이다.
- declaration은 payload type source를 제공하지만 JavaScript Socket.IO handler의 compile-time generic 강제는 Goal 4 전까지 없다.
- server/session/room/match/limiter의 single-process memory와 Goal 2 보안 잔여 위험은 변경하지 않았다.
