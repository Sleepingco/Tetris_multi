## Module과 보안 경계

- `src/server`의 production source `.js`는 0개다. `socketContracts.mjs`는 browser/server가 공유하는 Zod production runtime이므로 유일한 production `allowJs` 예외로 유지한다.
- root CommonJS와 NodeNext emit을 유지한다. server 간 정적 source import는 `.js`, server가 client ESM을 읽는 dynamic import는 `.ts`이며 compiled artifact에서 `.js`로 rewrite된다. root `type: module`과 TypeScript runtime loader는 추가하지 않았다.
- Room, Match, authoritative state, session, limiter, public DTO, log repository/validator와 Socket handler의 argument, return과 exported service 경계를 type-aware import/export로 연결했다. raw `require()` 결과를 `any`로 두거나 `@ts-ignore`, `@ts-nocheck`, 광범위한 assertion으로 오류를 숨기지 않았다.
- 모든 C2S raw payload는 `unknown`이며 기존 `clientToServerSchemas[event].safeParse(payload)`의 `validation.data`만 handler/service로 전달한다. schema, public wire 결과와 `parseClientEvent` 의미는 변경하지 않았다.
- handshake는 auth/address/credential 판별 → credential 없는 신규 session rate-limit → handshake schema parse → malformed resume rate-limit → authenticate → 인증 실패 resume rate-limit → 성공한 SocketData 설정 순서를 유지한다.
- mutation은 기존 active-session/rate-limit precheck → Zod → ownership → service 순서를 유지한다. production Socket.IO `Server`/`Socket` 타입을 fake union이나 `any`로 넓히지 않았고 SocketData에 token, digest나 internal session을 추가하지 않았다.

## Build, test와 release 계약

- `npm test`는 clean `build:server` 뒤 `test:compiled`를 실행한다. `test:compiled`는 build 없이 기존 artifact를 재사용하며 server source를 참조하던 Node test 20개와 benchmark runner는 `dist/server/**/*.js`를 사용한다.
- `scripts/verify.sh`는 typecheck → full build → artifact → `test:compiled` 순서다. full client/server artifact 뒤 server-only rebuild를 끼우지 않으며 `npm start`는 prebuilt `dist/server/app.js`만 실행한다.
- artifact test는 source/dist model byte equality와 SHA-256 `ff64b0d3e4cd9eb6c6d7920f2cbe961f1d70e4c90ccc69a5d9ab8bcd410cb33d`, default copied model의 실제 `placement_v4` decision과 returned `modelSha256`, compiled game core loader를 확인한다.
- 기존 `authoritativePlayerMutationQueue`에 token/session sentinel을 실제 room/player 인자로, 별도 고정 문자열을 non-function mutation으로 전달한 child는 예상대로 비정상 종료한다. 정확한 `mutation must be a function`, `dist/server/server/**/*.js` stack 위치, source-map remap 부재와 두 sentinel 비노출을 확인하며 새 production 오류 경로나 test-only hook은 만들지 않았다.
- hermetic release는 임시 디렉터리에 `dist`, package manifests와 `npm ci --omit=dev --ignore-scripts` production dependencies만 둔다. runtime cwd와 환경 allowlist를 고정하고 `NODE_PATH`, `NODE_OPTIONS`, model override와 workspace dependency 유입을 차단한다.
- source-less release에서 HTTP root와 Socket.IO client asset, authoritative PVP input, default model의 PVE `placement_v4` decision을 실행했다. 실제 Socket.IO auth/handshake는 compiled security tests와 Playwright에서 검증했다. release에는 source, test, scripts, e2e, devDependency, TypeScript/declaration/source map과 secret이 없다.
- 리뷰에서 TTL cleanup이 logger override 없이도 기존 `saveGameEventLog` fallback을 사용하도록 복구했다. 진행 중 session 만료 integration test는 임시 `GAME_EVENTS_LOG_PATH`에 `disconnect_timeout` game-over JSONL 한 줄만 저장되는지 확인하고 환경변수와 임시 파일을 복원한다.

## Bundle, 남은 위험과 rollback

- client production source와 dependency는 변경하지 않았다. final full build는 기존 Vite client entry/chunk 구성을 유지하며 이번 Goal의 배포 변화는 compiled server와 release 검증에 한정된다.
- Chromium local dev/production과 source-less release를 검증했지만 WebKit/Firefox, 외부 TLS/reverse proxy, 장시간 multiplayer/limiter soak는 실행하지 않았다.
- Express의 새 local declaration은 현재 사용하는 API surface만 좁게 표현한다. server가 더 넓은 Express API를 사용하게 되면 공식 type dependency 추가 여부를 별도 Goal에서 판단해야 한다.
- test/e2e/script 자체의 선택적 TypeScript 전환은 Goal 8D, persistent storage는 Goal 9 범위다.
- rollback은 `docs: finalize Goal 8C review gate` (현재 commit) → `0fa4f39` → `785dcf0` → `978398c` → `c8cdb9d` → `3a60750` → `e67ecf5` → `49187e4` 순서로 역순 revert한다. server rename과 compiled consumer 경로를 목적 경계별로 함께 되돌리며 generated artifact만 부분적으로 복구하지 않는다.
- pre-interop 문서 commit `7680229`는 구현 rollback 대상이 아니다.
- Goal 8C만 완료 처리하고 local merge gate에서 멈춘다. push, main merge, branch 삭제, Goal 8D/9와 SPA 작업은 수행하지 않는다.
