## 변경 계약

- T-Spin manual input은 grounded row보다 위인 row 12 이상에서 멈춘다. 회전 직전 최신 snapshot이 같은 human/piece의 `tree`, rotation 0, row 16, col 0, pending garbage 0과 기존 T-Spin 코너 board를 동시에 만족해야 한다.
- rotate 뒤 같은 `pieceIndex`의 더 최신 sequence에서 rotation 1, row 16, col -1 wall kick을 확인한 뒤에만 hard drop을 보낸다. 어느 precondition보다 `pieceIndex`가 먼저 증가하면 retry하지 않고 원인을 드러내는 precondition 오류로 실패한다.
- T-Spin 성공은 최종 `pieceIndex` 증가, score delta 15, line 불변, authoritative board의 T 조각 cell과 Canvas 변화로 검증한다. 키 호출 자체를 성공 증거로 사용하지 않는다.
- pending garbage는 기준 snapshot 이후 sequence와 piece index 증가, board fingerprint 변화와 garbage cell 증가로 실제 적용을 확인한다.
- 같은 authoritative sequence가 유지되는 동안 UI 숫자와 `is-danger` class가 최신 snapshot의 pending 값과 일치하는지 확인한다. lock 뒤 새 AI attack으로 pending이 다시 증가하는 정상 동작을 허용한다.
- fixed sleep, timeout 증가, retry, skip, worker 변경과 production debug/test API를 추가하지 않았다.
- score/Canvas 기준값 조회를 회전 precondition보다 먼저 수행한 중간 반복에서 T-Spin score는 15였지만 새 AI garbage가 고정 board를 위로 이동시킨 1건을 확인했다. gameplay 결함이나 lock-delay 실패가 아니므로 검사를 느슨하게 하지 않고, exact board 계약에 필요한 pending 0을 회전 전·후 authoritative 경계에 고정했다.
