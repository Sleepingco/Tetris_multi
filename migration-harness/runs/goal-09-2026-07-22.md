## dependency와 migration 결정

- 기존 runtime 기준인 Node `24.18.0`을 유지했다.
- PostgreSQL `18.4`, production `drizzle-orm@0.45.2`/`pg@8.22.0`, dev-only

- `pg`는 Goal 9에 필요한 Pool max, connection/query/statement timeout과 명시적

  credential을 포함하지 않는다.

## write·schema 계약

1. 공통 validator가 payload object, schema/event contract, 256 KiB 상한과 private-field
   변형을 검사한다.
2. JSONL append를 먼저 await하며 이 결과가 save/gameplay의 canonical 성공 경계다.
3. feature flag가 exact `true`일 때만 validated snapshot을 bounded in-memory queue에
   enqueue한다.
4. PostgreSQL은 parameterized Drizzle insert와 semantic SHA-256 primary key,
   `ON CONFLICT DO NOTHING`으로 first-write-wins shadow row만 추가한다.

`game_events`는 event/schema version, game/room/player/piece 검색 column,
`occurred_at`, JSONB payload, 원래 `JSON.stringify()` bytes의 SHA-256과 `stored_at`만
갖는다. 별도 sequence·derived table·read path는 만들지 않았다.

Idempotency identity:

- `game_start`: `[eventType, gameId]`
- `game_over`: `[eventType, gameId]`
- `placement_decision`: `[eventType, gameId, playerId, pieceIndex]`

## 장애·shutdown 계약

- queue capacity 기본 256은 in-flight를 포함한다. overflow는 newest event를 버리고
  payload 없는 warning을 남긴다.
- connection/query 기본 timeout은 각 1초, queue margin은 250ms, shutdown은 5초다.
  connection + query + margin이 shutdown보다 길면 configuration을 fail closed하고
  JSONL-only로 남는다.
- DB failure는 다음 event를 계속 처리한다. queue-level timeout은 writer를 비활성화하고
  pending event를 버려 unresolved write가 queue 밖에서 누적되지 않게 한다.
- SIGINT/SIGTERM은 Socket.IO close → shadow queue flush → Pool close 순서로 처리한다.
  설정 가능한 flush 최대는 60초이고 전체 server shutdown은 65초에 fail-fast한다.
- 즉시 rollback은 `POSTGRES_SHADOW_WRITE_ENABLED`를 끄고 server를 재시작하는 것이다.
  DB row는 자동 삭제하지 않으며 JSONL은 계속 사용한다.

## 보안·데이터 계약

- runtime `DATABASE_URL`, migration `MIGRATION_DATABASE_URL`, integration
  `TEST_DATABASE_URL`을 분리한다. 실제 URL/credential은 source, image, 문서, test
  output과 warning에 기록하지 않았다.
- 원격 URL은 `sslmode=verify-full`을 정확히 한 번 포함해야 한다. plain connection은
  localhost/loopback integration DB에만 허용하며 `rejectUnauthorized:false`는 없다.
- 공통 validator와 repository defense-in-depth는 중첩된 token, api key, auth,
  credential, cookie, password/private key, secret, reconnect/session/socket identifier,
  expiry/generation field 변형을 재귀적으로 거부한다.
- runtime role은 `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS`이며
  schema USAGE, 지정 column INSERT와 idempotency-key SELECT만 필요하다. UPDATE, DELETE,
  TRUNCATE, schema CREATE와 migration history 접근은 주지 않는다.
- payload에는 public nickname, player/room id와 행동 telemetry가 포함될 수 있다.
  Goal 9는 purge를 추가하지 않는다. 실제 사용자 보존 기간과 maintenance owner가
  승인되기 전에는 production feature flag를 활성화하지 않는다.

## 실제 PostgreSQL 검증

Homebrew PostgreSQL `18.4`를 설치했지만 service 등록은 하지 않았다. 기본 cluster를
loopback port `55439`에서만 임시 기동하고 검증 직후 중지했다. URL에는 password를
사용하지 않았으며 run record에 실제 credential은 없다.

`npm run test:db` 1/1에서 확인한 항목:

- random empty schema 최초 migration과 `game_events` 0 row
- 같은 migration 재실행 뒤 `__drizzle_migrations` 1 row
- 같은 placement event 두 번 append 뒤 1 row
- JSONB payload, 원문 SHA-256, semantic idempotency key와 timestamptz
- 임시 NOLOGIN runtime role의 INSERT/idempotency-key SELECT 성공
- payload SELECT, UPDATE, DELETE, TRUNCATE와 schema CREATE 거부
- test 종료 후 임시 schema와 role 0개

첫 최소권한 test는 `Pool.query()`가 권한 오류 뒤 연결을 교체해 후속 assertion을
superuser로 실행하면서 실패했다. 한 checked-out client에서 `SET ROLE`을 유지하도록
고쳐 같은 gate가 통과했으며 실패 실행이 남긴 임시 role도 제거했다.

운영 CLI도 고정 test schema에 두 번 실행해 두 번 모두 성공하고 migration history
1/event 0을 확인한 뒤 schema를 제거했다. PostgreSQL process도 정상 중지했다.

## 남은 위험과 rollback

- WebKit/Firefox, managed PostgreSQL의 실제 CA/hostname·SCRAM 환경, 외부 network와
  장시간 DB/queue soak는 실행하지 않았다.
- Homebrew `postgresql@18`과 초기화된 기본 cluster는 로컬 도구로 남지만 background
  service는 실행 중이 아니다.
- 자동 retention job이 없으므로 production enable 전에 보존 기간과 owner 결정이
  필요하다.
- commit rollback은 최종 문서 commit → `fbb800e` → `fdb4a83` → `b9474da` 순서로
  역순 revert한다. 먼저 feature flag를 끄고 JSONL-only로 복귀한 뒤 code/migration을
  되돌리며 이미 저장된 DB row를 application rollback과 섞어 삭제하지 않는다.
- Goal 9만 완료 처리하고 merge gate에서 멈춘다. push, main merge, branch 삭제,
  Goal 8D/10과 SPA 작업은 수행하지 않는다.
