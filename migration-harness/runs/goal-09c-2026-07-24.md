## 구현 계약

### Streaming과 입력 보호

- `createReadStream`, byte-counting `Transform`과 `readline`으로 JSONL을 한 줄씩 읽으며 전체 파일을 memory에 적재하지 않는다.
- raw line과 canonical envelope 각각 `256 KiB` 상한을 유지한다.
- 첫 pass에서 계산한 source SHA-256을 종료 시 별도 streaming pass로 다시 확인해 import 도중 원본 변경을 fail closed한다.
- report output은 source와 같은 canonical path 또는 inode를 가리킬 수 없다. importer는 원본 JSONL을 쓰거나 삭제하지 않는다.
- 검증 전 `eventType`은 allowlist 밖의 원문을 report key로 복사하지 않고 `unknown` count로만 집계한다.

### Projection, identity와 privacy

- 각 line은 기존 `validateGameEventLog`, `projectGameEventLog`, `prepareCanonicalGameEvent` 경계를 그대로 통과한다.
- 기존 canonical identity tuple, canonical JSON, SHA-256 event ID/event hash와 privacy allowlist를 별도 구현하지 않고 재사용한다.
- legacy lifecycle v1 game over는 기대 placement count가 없는 canonical lifecycle v1으로 보존한다. 현재 lifecycle v2는 기대 count와 receipt policy metadata를 유지한다.
- 금지된 privacy key는 normalized recursive key 검사에서 fail closed하며 issue에는 safe reason code와 line number만 남긴다.

### Dry-run, append와 복구

- dry-run은 validation, projection, identity와 completeness를 모두 실행하지만 DB connection이나 append를 수행하지 않는다.
- write mode는 `IMPORT_DATABASE_URL`만 읽고 `DATABASE_URL` fallback을 사용하지 않는다. 기존 strict URL/TLS/ambient `PG*` 차단과 PostgreSQL repository를 재사용한다.
- append는 sequential이며 inserted/duplicate/conflict를 구분한다. 재실행은 exact event를 duplicate로 처리하고 기존 row를 UPDATE하지 않는다.
- DB append failure가 발생하면 새 append는 멈추되 나머지 source를 계속 streaming validation해 source hash와 report를 완성한다. 수정 후 같은 immutable source를 다시 실행하면 이미 저장된 row는 duplicate, 남은 row는 inserted가 되어 partial failure에서 복구된다.
- issue 목록은 최대 `100`개로 제한하고 전체 count를 별도로 유지한다.

### Completeness

game별 raw identity 대신 digest만 report하며 다음 reason code를 집계한다.

- `lifecycle_start_missing`, `lifecycle_start_duplicate`
- `lifecycle_over_missing`, `lifecycle_over_duplicate`
- `lifecycle_mode_mismatch`, `lifecycle_membership_mismatch`
- `placement_player_membership_mismatch`
- `placement_duplicate`, `placement_internal_gap`
- `placement_tail_count_mismatch`
- `legacy_unknown_tail`
- `idempotency_conflict`

`complete`만 ML export eligible이다. lifecycle v1처럼 expected tail을 증명할 수 없는 경우는 `ambiguous`, start/over 누락이나 membership·sequence 불일치는 `incomplete`로 분리한다. Goal 9C는 dataset read-source를 PostgreSQL로 전환하지 않는다.
기존 DB row와 immutable hash가 다른 conflict도 해당 game을 `incomplete`와 ML export 제외로 표시한다.

## 남은 위험과 미검증 범위

- production OCI PostgreSQL import, managed credential/CA와 실제 사용자 DB는 접근하거나 검증하지 않았다.
- write mode는 명시된 `IMPORT_DATABASE_URL`이 production인지 기술적으로 판별하지 않는다. production import는 별도 승인, URL 확인과 최소 권한 import role이 필요한 운영 gate다.
- hosted PostgreSQL service와 branch CI는 push 전이므로 실행하지 않았다. 이는 Goal 9D 범위다.
- lifecycle v1은 expected placement count가 없어 tail completeness를 증명할 수 없다.
- import report는 운영 승인 자료일 뿐 자동 retention, deletion, retry daemon이나 queue가 아니다.
- JSONL은 계속 기본 runtime sink이며 production PostgreSQL 활성화와 DB dataset read-source 전환은 하지 않았다.
