## 승인된 제한적 예외

preflight의 첫 E2E는 `.codex` worktree에서 `/`가 404를 반환해 web server readiness timeout으로 실패했다. 절대 경로의 `.codex` segment를 Express `send@1.2.1`이 dotfile 경로로 판단한 것이 원인이었다.

사용자가 Goal 0의 제한적 범위 예외로 `src/server/init.js`의 root `sendFile()` 한 줄 수정을 승인했다.

- 적용: `res.sendFile("pages/index.html", { root: STATIC_ROOT });`
- 미적용: `dotfiles: "allow"`, redirect, Playwright readiness 우회, 서버 구조 리팩토링
- 이 예외는 baseline E2E 변경과 별도 commit `45f4c2a`로 기록했다.

## 실패와 미실행 범위

- dependency 복원 전 첫 E2E는 local Playwright binary 부재로 실행되지 않았다. `npm ci` 후 재시도했다.
- 수정 전 E2E는 root 404로 readiness timeout이 발생했고, 승인된 호환성 예외 적용 후 재현되지 않았다.
- packet loss, 높은 외부 latency, 장시간 soak, WebKit과 Firefox는 검증하지 않았다.
- Node 24 전환은 Goal 1 범위이므로 수행하지 않았다.

## 보안·데이터 영향

- `dotfiles: "allow"`를 사용하지 않아 dotfile 노출 범위를 넓히지 않았다.
- session, reconnect, authorization과 Socket.IO payload 계약은 변경하지 않았다.
- test fixture에 token, secret, 개인 데이터를 추가하지 않았다.
- JSONL, Python parity, dataset, model artifact와 production log를 변경하지 않았다.

## 남은 위험

- known rollback 재현 없음은 local Chromium 고정 시나리오에 한정된다.
- input monitor는 Playwright의 WebSocket frame 관찰 API에 의존한다.
- Goal 0이 main에 반영된 뒤 같은 gate를 다시 통과하기 전에는 migration 기준선으로 확정할 수 없다.

## Rollback

- code/test rollback 지점은 `803c569`, `45f4c2a`다.
- 문서 rollback 지점은 `f9882db`와 실행 기록 commit이다.
- merge 전에는 branch commit을 역순으로 revert하면 기준 main으로 돌아갈 수 있다.
- 기존 stabilize branch, main과 Local checkout은 변경하거나 삭제하지 않았다.

- Goal 0 범위의 code/test/document 변경과 검증은 준비됐다.
- push, PR, main merge, 기존 branch 삭제와 Goal 1은 수행하지 않는다.
- 사용자 검토와 명시적 merge 승인에서 멈춘다.
