## 구현 계약

- `Dockerfile`은 official `node:24.18.0-bookworm-slim@sha256:6f7b03f7c2c8e2e784dcf9295400527b9b1270fd37b7e9a7285cf83b6951452d`를 build, production dependency와 runtime stage에 고정한다.
- build stage는 lockfile로 `npm ci --ignore-scripts` 후 기존 `npm run build`를 실행한다. production dependency stage는 `npm ci --omit=dev --ignore-scripts`만 수행한다.
- runtime에는 production `node_modules`와 `dist/client`, `dist/server`만 복사한다. `/app/data/logs`는 built-in `node` user 소유이며 운영 시 read-only root와 별도 volume을 함께 사용한다.
- `.dockerignore`는 dependency, build output, test/e2e, Python/Conda, harness/docs, data, environment, key와 log를 build context에서 제외하고 기존 `scripts/build.js`만 허용한다.
- runtime secret과 `SOCKET_ALLOWED_ORIGINS`, `CSP_CONNECT_ORIGINS`, `GAME_EVENTS_LOG_PATH`는 image layer에 넣지 않고 실행 환경 또는 승인된 mount에서 주입한다. 검증 container의 `SOCKET_RATE_LIMIT_PROFILE=test`는 Playwright 부하 전용이며 production 배포 계약이 아니다.
- health check는 Node 내장 `fetch()`로 `/`의 성공 여부만 확인한다. token, credential, room/match와 내부 상태를 반환하는 새 endpoint는 만들지 않았다.
- SIGTERM은 handler disposer를 한 번만 실행해 session cleanup interval, disconnect grace timer와 room ticker를 정리한 뒤 Socket.IO의 HTTP server close를 기다린다. 8초 안에 끝나지 않으면 exit 1로 종료한다.
- production same-origin polling의 no-Origin browser 요청은 `Sec-Fetch-Site: same-origin`과 allowlisted `Host`가 모두 맞을 때만 허용한다. explicit cross-origin 요청은 기존 exact `SOCKET_ALLOWED_ORIGINS`로 검증하며 일반 no-Origin과 unlisted host/origin은 거부한다.
- Playwright 기본 production/Vite-dev server 동작은 유지하고, `PLAYWRIGHT_EXTERNAL_SERVER=1`일 때만 이미 실행 중인 container를 사용한다.

## 남은 위험과 rollback

- Docker Desktop linux/arm64에서만 image를 실행했다. buildx가 linux/amd64를 지원하는 것은 확인했지만 amd64 build/run은 수행하지 않았다.
- 외부 TLS termination, 실제 production hostname/reverse proxy의 Host 보존, registry publish/provenance/signature/SBOM과 장시간 soak는 미검증이다.
- 첫 production image라 이전 production digest로 실제 downgrade할 대상은 없다. 현재 검증은 동기화 commit tag `tetris-multi:goal11c-6d09a28`와 새 image ID 재실행까지다.
- 다음 배포부터는 새 digest 전환 전에 기존 registry digest를 보존하고, 실패 시 그 digest를 고정해 동일한 read-only root, volume과 runtime environment로 재기동한다. mutable tag만으로 rollback하지 않는다.
- main 동기화만 되돌릴 때는 최종 문서 commit을 먼저 revert한 뒤 merge commit `6d09a28`을 mainline 1 기준으로 revert한다. Goal 11C 자체 rollback은 최종 문서 commit을 먼저 revert한 뒤 `d13abfb` → `1c09fec` → `9554bbc` 순서로 역순 revert한다. package/lockfile과 Python/Conda 파일은 변경하지 않았다.
- Goal 11C merge gate에서 멈춘다. push, main merge, image publish/deploy, branch 삭제와 Goal 11D는 수행하지 않는다.
