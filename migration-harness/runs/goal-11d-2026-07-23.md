## Workflow 계약

- `.github/workflows/ci.yml` 하나가 `pull_request`와 `main` push, 수동 dispatch에서 실행된다. workflow 권한은 `contents: read`뿐이며 `pull_request_target`, secret, registry, deployment와 write 권한은 없다.
- 공식 `actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd`(`v6.0.2`)와 `actions/setup-node@48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e`(`v6.4.0`)만 사용한다. 두 SHA는 official tag ref에서 확인했다.
- concurrency group은 workflow와 ref 단위이며 새 실행이 같은 ref의 진행 중 run을 취소한다. timeout은 fast 10분, browser 20분, docker 15분이다.
- `fast`는 full checkout 후 PR base..head 범위의 `git diff --check`, `.nvmrc` exact Node 검사, 실제 npm 버전 출력, `npm ci --ignore-scripts`, `bash scripts/verify.sh`와 `npm run test:release`를 실행한다.
- `browser`는 fast artifact를 재사용하지 않는다. 독립 checkout·Node setup·clean install 뒤 `npx --no-install playwright install --with-deps chromium`, Vite-dev gate와 production 전체 Playwright를 기존 `playwright.config.cjs` webServer lifecycle로 실행한다. workers 1과 retries 0을 유지한다.
- `docker`는 registry에 push하지 않고 run ID와 attempt를 포함한 local tag, container와 volume 이름을 사용한다. read-only root와 JSONL 전용 volume, CI localhost의 Socket/CSP origin, bounded health loop의 즉시 unhealthy 실패, HTTP/security header와 first-party source/map 404, 명시적 stop 후 exit 0을 검사하고 trap으로 container와 volume을 정리한다. gameplay E2E는 browser job과 중복하지 않는다.
- setup-node npm cache는 `package-lock.json`을 dependency path로 사용한다. cache miss에도 각 Node job이 `npm ci --ignore-scripts`를 수행하며 `node_modules`와 browser binary는 cache하지 않는다.
- Playwright trace, HTML report와 `e2e-game-events.jsonl`을 포함해 workflow artifact는 전혀 업로드하지 않는다. 별도 redaction 정책이 승인되기 전까지 실패 artifact를 보류한다.

## Token-safe assertion

- token 길이, rotation, BFCache/reconnect와 stale credential 보존 비교는 token 원문을 matcher의 actual/expected에 넘기지 않고 boolean 결과만 검증한다.
- URL, HTML과 수집된 console message의 token 비노출도 `includes(token) === false`의 boolean 결과로 검증한다. 검증 대상과 실패 의미는 기존과 같고 실패 log에는 token 원문이 matcher 값으로 출력되지 않는다.
- `tokenDigest`처럼 원문 credential이 아닌 금지 field 이름 검사는 기존 문자열 matcher를 유지한다.

## CI 실행 승인 gate와 남은 위험

- branch protection 연결 후보 required check는 `Migration CI / Fast gate`, `Migration CI / Chromium PVP and PVE`, `Migration CI / Production container smoke`다. 실제 check 이름은 첫 GitHub run에서 확인한 뒤 별도 승인으로 연결한다.
- 현재는 local macOS/arm64와 Docker linux/arm64에서 workflow shell 계약을 검증했다. GitHub-hosted `ubuntu-24.04`의 clean run, cache miss/hit, Chromium OS dependency 설치와 Docker daemon 차이는 미검증이다.
- Goal 완료 기준인 clean CI run과 의도적인 type/build/unit/E2E failure routing은 workflow를 push하지 않아 미검증이다. artifact가 없으므로 실패 분석은 현재 workflow log에 한정된다.
- ML parity는 Conda 환경 설치 비용과 별도 action 공급망 검토가 필요해 required CI에서 제외했다. 재개하려면 별도 수동 workflow 승인을 받는다.
- 실제 GitHub 실행 전에는 Goal 11D를 complete 처리하지 않는다. 현재 상태는 CI 실행 승인 gate다.
