## 구현 계약

### Migration과 schema

- `MIGRATION_DATABASE_URL`만 읽는 compiled CLI와 `MIGRATION_LOCK_TIMEOUT`의 1~60,000ms bounded contract를 추가했다. `DATABASE_URL` fallback은 없다.
- 고정 advisory lock 아래 history bootstrap과 migration별 transaction을 실행한다. 이미 적용된 version의 name/checksum 불일치, invalid artifact와 lock timeout은 fail closed한다.
- 실패 시 open transaction rollback, advisory unlock과 connection close를 순서대로 각각 시도한다.
- 고정 `tetris_analytics` schema에 `schema_migrations`와 append-only `game_events` 한 table만 만든다. application migration은 role과 database를 생성하지 않는다.
- `schema_migrations`는 양의 version, nonblank name, lowercase SHA-256 checksum과 DB-owned applied time을 검사하고 PUBLIC 권한을 제거한다.
- `game_events`는 identity-v1, 세 event type, event별 schema/time/trust/null shape, nonblank identity, object JSONB와 lowercase digest를 CHECK한다.
- lifecycle과 placement semantic partial unique index, `game_id`, `(event_type, ingested_at)` index만 둔다. runtime INSERT에는 DB-owned `ingested_at`이 없다.

### Canonical event와 repository

- repository 입력은 runtime validation을 통과한 `CanonicalGameEvent`이며 raw JSONL projector는 만들지 않았다.
- canonical JSON은 JSON primitive, array와 plain object만 허용하고 `Object.keys(value).sort()`를 재귀 적용한다. array 순서를 보존하고 Unicode normalization과 locale comparison을 하지 않는다.
- non-finite number, BigInt, undefined, sparse array, custom prototype/toJSON/getter, symbol, function과 cycle을 거부한다. occurred time은 유효한 UTC millisecond ISO로 정규화한다.
- canonical envelope 전체의 UTF-8 byte 길이는 256 KiB 이하이며 deep-frozen snapshot 하나를 hash와 INSERT 양쪽에 사용한다.
- `event_id`는 original semantic identity tuple, `event_sha256`은 event ID와 DB-owned ingestion time을 제외한 immutable canonical envelope에서 Node 표준 SHA-256으로 계산한다.
- repository는 explicit connection URL/CA를 주입받고 schema-qualified parameterized INSERT와 별도 conflict SELECT만 실행한다. UPDATE는 없다.
- INSERT가 충돌하면 event ID 또는 semantic tuple로 최대 두 row를 읽는다. 정확히 한 row의 event ID, tuple과 hash가 모두 같을 때만 duplicate이며 나머지는 `IDEMPOTENCY_CONFLICT`다.
- invalid/closed repository는 고정 code로 실패하고 `close()`는 같은 Promise를 재사용한다. gameplay runtime과 `DATABASE_URL` wiring은 없다.

### Connection, role과 artifact

- URL은 한 번 parse하고 unknown/duplicate/unsafe query option을 거부한다. 원래 connection string은 pg에 다시 넘기지 않고 allowlisted `ClientConfig` field만 구성한다.
- loopback test만 non-TLS를 허용한다. non-loopback은 DNS hostname, `sslmode=verify-full`, `rejectUnauthorized: true`와 explicit server name을 요구한다. provider CA는 caller가 필요한 환경에서만 명시한다.
- integration admin provisioning은 migration role을 schema/table owner로 두고 runtime role에는 analytics USAGE, 정확한 INSERT columns, semantic key/hash SELECT와 migration history version/name/checksum SELECT만 준다.
- runtime role은 제한된 search path를 사용하며 CREATE/DDL/UPDATE/DELETE/TRUNCATE, migration membership, privileged role attribute, payload/ingestion SELECT와 `ingested_at` INSERT가 거부된다.
- build helper는 SQL migration을 compiled server에 byte-identical copy한다. 기존 DB-free `test:release`는 바꾸지 않았고 `test:db`의 별도 production-dependency source-less fixture에서 compiled migration을 두 번 실행하고 repository를 load했다.

## Rollback과 merge gate

application rollback은 목적별 commit을 역순으로 revert한다.

1. 이 verification 문서 commit을 revert한다.
2. `8469fd0` test commit을 revert한다.
3. `7d1529b` repository commit을 revert한다.
4. `c090203` migration/build/dependency commit을 revert한다.

기존 Blueprint 세 commit은 설계 기록으로 보존할 수 있다. Goal branch 전체를 폐기하기로 별도 승인하면 `22a7d7e` → `a78a10a` → `b15d704` 순으로 추가 revert한다.

이미 생성된 PostgreSQL schema, table과 row는 자동 drop하거나 down migration하지 않는다. DB data 삭제는 별도 사용자 승인 사항이며 code rollback 뒤에도 현재 JSONL runtime은 그대로 동작한다.

Goal 9A local 완료 조건까지만 충족했다. push, PR, main merge, branch/worktree 삭제, production DB 활성화와 Goal 9B는 수행하지 않고 merge gate에서 멈춘다.
