## 위협 모델과 보안 선택

| 위협 | 적용한 통제 | 남는 경계 |
| --- | --- | --- |
| 다른 playerId를 payload에 넣는 mutation 위조 | 모든 identity를 검증된 socket session에서 파생하고 room membership을 재검증 | public playerId는 표시·분석용이므로 비밀이 아니다 |
| token brute force와 timing oracle | 256-bit CSPRNG token, SHA-256 digest 저장, `timingSafeEqual`, invalid resume 독립 rate bucket | limiter는 단일 process memory이며 분산 rate limit이 아니다 |
| token replay와 duplicate tab | 매 resume token/generation rotation, newest socket wins, 이전 socket 즉시 disconnect | sessionStorage token을 탈취한 공격자는 가장 최신 token으로 한 번 경쟁할 수 있다 |
| transport 중단 중 credential 손실 | 직전 token을 active socket이 없을 때 60초 안에 한 번만 recovery | 60초 이후 또는 server restart 후에는 새 identity가 필요하다 |
| stale async/queued side effect | input queue와 placement log가 side effect 직전에 active socketId/generation을 다시 검사 | 이미 완료된 side effect는 reconnect로 rollback하지 않는다 |
| disconnect 직후 membership 탈취/유실 | playerId, generation, disconnectedAt을 캡처한 30초 grace와 실행 직전 재검사 | process restart 시 in-memory room/session이 함께 사라진다 |
| private session metadata 유출 | room/player whitelist DTO, private log field 거부, generic auth error, raw connection log 제거 | application error stack을 외부 관측 시스템에 보내는 별도 logging 정책은 범위 밖이다 |
| cross-origin Socket.IO abuse | production exact origin allowlist 필수, CORS와 `allowRequest` 동시 적용 | TLS는 배포 proxy에서 종료해야 하며 production origin은 HTTPS exact 값으로 구성해야 한다 |
| oversized payload와 event flood | 512 KiB buffer와 event 성격별 독립 bucket | 장시간/분산 abuse soak는 수행하지 않았다 |

서버 session map에는 token digest, generation, activeSocketId, canonical nickname과 최초 발급 기준 8시간 절대 expiresAt만 둔다. roomId는 session에 저장하지 않으며 기존 `roomService` membership이 단일 진실 원천이다. token rotation은 절대 만료를 연장하지 않는다.

production transport는 HTTPS/WSS를 제공하는 TLS termination 뒤에서 Socket.IO polling/WebSocket upgrade를 유지하는 정책이다. `SOCKET_ALLOWED_ORIGINS`가 없으면 production bootstrap이 실패한다. trusted proxy를 설정하지 않았으며 limiter key에 `X-Forwarded-For`를 사용하지 않는다.

## 변경 전후 event 계약

공통 bootstrap 계약:

| 단계 | 변경 전 | 변경 후 |
| --- | --- | --- |
| Socket 생성 | 즉시 연결, browser playerId 사용 | `io({ autoConnect: false, auth: callback })`; `session:ready`/`connect_error` listener 등록 후 connect |

## 보안·데이터 영향

- browser에는 `tetris:playerSession` 하나로 `{version, playerId, token, nickname, expiresAt}`을 원자 저장한다. legacy `tetris:playerId`는 제거한다.
- token 원문은 발급/rotation 시 해당 private socket의 `session:ready`와 sessionStorage에만 존재한다. 서버 memory에는 digest만 유지한다.
- room/game public payload는 whitelist mapper를 사용한다. token, digest, session generation, socketId와 expiry는 room DTO, result, opponent-left, match-finish, log와 generic auth error에 포함하지 않는다.
- public playerId와 roomId는 기존 display, authoritative match와 분석 lineage를 위해 유지한다.
- JSONL event/placement schema의 gameplay/ML 의미는 변경하지 않고 placement playerId만 authenticated session 값으로 덮어쓴다.

## 기존 클라이언트 호환성

- 기존 playerId-only credential은 incomplete auth로 거부한다. controlled migration 환경에서 terminal error가 저장 identity/room을 지우고 server-issued 신규 session을 한 번 받는다.
- room membership을 session에 복사하지 않으므로 invalid/expired credential에서 신규 identity를 받은 client는 기존 room을 자동 탈취하거나 복구하지 않는다.
- 정상 reload/reconnect는 최신 token으로 같은 playerId를 resume하고 room sync/game join을 자동 수행한다.
- pagehide는 더 이상 즉시 leave가 아니므로 reload와 짧은 network loss가 같은 30초 grace를 공유한다. 명시적 Leave/Home 의미는 유지한다.

## 남은 위험과 미실행 범위

- session, room, match와 limiter가 process memory에 있으므로 server restart와 multi-instance 공유를 지원하지 않는다. Redis 도입은 제외 범위다.
- sessionStorage token은 same-origin XSS로 읽힐 수 있다. CSP, 전체 payload schema와 broader HTML/input hardening은 이번 Goal 범위가 아니다.
- newest socket wins는 duplicate tab을 명시적으로 지원하는 정책이 아니다. 같은 credential의 마지막 연결만 활성이고 이전 tab은 terminal/stale 상태가 된다.
- 신규 session 120/분/IP는 brute-force resume bucket과 분리돼 있다. 실제 public deployment 전 traffic 특성에 맞춘 load/abuse test와 edge rate limiting이 필요하다.
- local Chromium과 loopback network만 검증했다. TLS termination, reverse proxy remote address, cross-region latency, WebKit/Firefox와 장시간 reconnect/soak는 미실행이다.
- placement log 저장 자체가 이미 완료된 직후 socket이 교체되면 저장 결과는 유지하고 stale socket response만 억제한다. 완료된 side effect를 rollback하지 않는 것이 의도된 경계다.

## Rollback

- controlled environment에서 문서 commit, browser session commit `3ae4efd`, server security commit `358d34f`를 역순으로 revert하면 기준 main의 playerId-only protocol로 돌아갈 수 있다.
- server/client protocol commit은 반드시 함께 rollback한다. 한쪽만 되돌리면 handshake와 mutation payload가 호환되지 않는다.
- rollback 동안 public Internet 배포를 허용하지 않는다. legacy playerId-only 경로를 feature flag나 기본 bypass로 남기지 않았다.
- session은 memory-only이므로 rollback/restart 시 기존 `tetris:playerSession`은 legacy client가 사용하지 않는다. 필요하면 controlled client storage reset을 안내한다.
