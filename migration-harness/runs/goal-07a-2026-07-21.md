## 구현 결정

- `src/client/pages/index.html` 하나만 application shell로 사용하고 `spa.tsx`의 `React.StrictMode` root 하나가 다섯 allowlisted pathname을 렌더링한다.
- framework 없이 History API와 `spaNavigation.ts`의 작은 route/exit 경계만 사용한다. legacy `.html` URL과 multiplayer query는 그대로 유지하고 `history.state`에는 private state를 저장하지 않는다.
- index/single route는 eager, lobby/multiplayer와 `roomClient`는 lazy import한다. production artifact에서도 classic `/socket.io/socket.io.js`가 SPA module보다 먼저 오도록 두 script를 head 안에서 순서 고정하고 artifact test로 검증한다.
- Express와 Vite dev rewrite는 `/`, 네 legacy page pathname에만 적용한다. unknown route/asset, Socket.IO, TSX와 source map은 broad fallback 대상이 아니다.
- route마다 기존 `style.css` 또는 `tetris.css` 하나만 활성화하고 title, focus, announcement, theme pre-paint와 sound preference를 유지한다.
- page component는 route export만 제공한다. route unmount는 runtime, keyboard, timer/animation, display/Socket subscription과 sound를 idempotent하게 정리한다.

## Socket과 leave lifecycle

- `roomClient`가 singleton Socket transport와 session credential을 계속 소유한다. SPA 이동 자체는 reconnect나 token rotation을 만들지 않는다.
- lobby→game과 finished game→lobby는 membership을 유지한다. waiting lobby 이탈은 `room:leave`, active game 이탈은 `game:leave`를 한 번 전송한다.
- 연결이 끊긴 route 이탈은 public `{roomId, kind}` 하나만 bounded memory intent로 저장한다. 다음 유효한 `session:ready`에서 page의 sync/join callback보다 먼저 한 번 flush하고 기존 result, terminal disconnect 또는 pagehide에서 정리한다.
- terminal disconnect를 늦게 구독한 lazy route에는 cancelable microtask replay를 한 번 제공한다. 새 connect/ready, unsubscribe와 기존 disconnect 중복에서는 stale terminal 알림을 전달하지 않는다.
- 새 Socket event/schema, session/token 정책, gameplay/AI/placement log 의미는 추가하거나 변경하지 않았다.

## 수동 확인과 발견 사항

- production Chromium에서 index→single→history back→lobby shell을 실제 UI로 이동해 title, 활성 stylesheet, route focus, Canvas 300×600, sound 상태 보존과 console error 0을 확인했다.
- 이 과정에서 Vite가 body의 module entry를 head로 hoist해 production artifact의 Socket.IO 선행 순서가 깨질 수 있음을 발견했다. script를 head 안에서 classic→module 순으로 고정하고 `1fa6808`과 artifact test로 회귀를 막은 뒤 모든 gate를 재실행했다.
- Codex in-app Browser에서는 classic Socket.IO global이 노출되지 않아 수동 PVP/PVE 연결 시나리오는 완료하지 못했다. 대신 프로젝트 Playwright Chromium에서 PVP/PVE 전체 flow와 bootstrap을 최종 41/41로 검증했으며 이 차이를 application 실패로 숨기지 않는다.

- 첫 `npm ci`가 shell 기본 Node 22에서 실행된 사실을 확인해 결과를 폐기하고 명시적인 Node 24 PATH로 다시 동기화했다. repository dependency와 lockfile은 바뀌지 않았다.
