## Display snapshot과 session cleanup

- 기존 cached display snapshot에 `pendingGarbageLines`만 추가했다. private pending queue, board, bag과 raw authoritative snapshot은 노출하지 않는다.
- pending 값이 같으면 snapshot reference와 알림 수를 유지하고 pending-only 갱신은 1회 알린다. `applySnapshot()`은 setter publish를 억제한 뒤 최종 display를 한 번만 publish한다.
- own correction은 pending 적용 전 local snapshot으로 판단한다. forced correction, game-over와 실제 correction은 `applySnapshot()`만 사용하고 deferred input은 pending 표시만 먼저 갱신할 수 있다.
- `startMultiplayerGame()`의 idempotent `destroy()`는 heartbeat, 기존 Socket disposer 5개, pending/deferred input, placement-log buffer, bag request와 두 runtime을 정리한다. destroy 전에 캡처한 interval/Socket/keyboard/animation callback을 실행해도 input, log, display와 network mutation이 생기지 않는다.

## React page와 lifecycle

- `tetrisMulti.html`은 기존 head, theme pre-paint, CSS, URL과 classic Socket.IO script 선행 순서를 유지하고 body를 `#multiplayerRoot`와 `tetrisMulti.tsx` entry로 옮겼다.
- 단일 `React.StrictMode` root가 Host=`data-player="1"`, Guest/AI=`data-player="2"`의 stable Canvas를 렌더한다. runtime에는 두 Canvas만 전달하고 React가 score, lines, incoming, hold/next preview, role badge와 match/disconnect overlay를 소유한다.
- gameplay state와 authoritative match는 runtime/server의 단일 진실 원천이다. React state에는 공개 page 정보, display handle과 overlay만 두며 token, socketId, full session, raw match/snapshot, board와 bag을 저장하지 않는다.
- display handle은 disconnect/match finish의 session destroy 뒤에도 마지막 HUD를 유지한다. reconnect join 성공 시 새 handle로 교체하며 terminal duplicate-tab 상태에서는 credential을 지우지 않고 입력을 차단한다.
- join gate는 disposed, terminal, matchFinished, joinPending과 active session을 검사한다. 최초 ready에서 `game:join` 1회, transport reconnect 뒤 새 ready에서 정확히 1회 추가하며 stale join result는 소비하지 않는다.
- effect는 placement result, game join, PVE policy, match finish, opponent left와 session ready/error/disconnected의 8개 disposer를 해제한다. sound, theme/home listener, navigation timer, game session과 pagehide/pageshow도 idempotent하게 정리하며 `pageshow.persisted` reload를 보존한다.
- review fix는 React state에 `session.myGame`/`opponentGame` 전체 객체를 두지 않고, 각 runtime에서 `getDisplaySnapshot`과 `subscribeDisplay`만 투영한 page-local handle을 보관하게 했다. fake Socket test는 authoritative snapshot, input result, bag append와 bag result handler가 destroy 전 각각 1개, 후 각각 0개인지 확인한다.
- reconnect E2E는 disconnect 전 상대 hold preview, offline 중 마지막 HUD 유지와 reconnect 뒤 player 1/2 overlay 모두 hidden을 확인한다. `aria-live`/`aria-atomic`은 중복 낭독을 피하기 위해 사용자 소유 game overlay에만 적용한다.

## Browser, 보안과 artifact 확인

- Vite-dev에서 player별 초기 `game:join` 1회, reconnect 뒤 +1회, 단일 input +1회와 authoritative acknowledgment를 확인했다.
- session당 heartbeat/timer와 Socket handler는 한 세트이며 destroy 뒤 캡처 callback은 mutation을 만들지 않는다. PVE pending 증가/감소의 `is-danger`, placement V4 badge/fallback, Canvas 300×600, preview cell/class와 incoming ARIA 계약도 유지한다.
- synthetic `pagehide → pageshow.persisted → reload` 뒤 새 session/join을 복구한다. current-token 중복 연결은 terminal 안내와 input 차단을 만들고 credential은 보존한다.
- Host/Guest token은 URL, HTML과 수집한 console message에 없고 browser console error/pageerror는 0개다. production `/pages/tetrisMulti.tsx`와 built module `.map`은 404다.
- dependency와 server runtime이 바뀌지 않았으므로 production dependency-only 재설치는 Goal 4/5 결과를 중복하지 않았다. clean artifact gate와 production HTTP/Playwright가 현재 compiled output을 검증한다.
