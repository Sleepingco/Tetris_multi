## 변경과 불변조건

- `index.html`과 `multiLobby.html`의 head, theme pre-paint, CSS와 URL을 유지하고 body를 각각 `index.tsx`, `multiLobby.tsx`의 독립 StrictMode root로 옮겼다.
- lobby의 classic Socket.IO script는 TSX module보다 먼저 로드된다.
- 기존 ID, class, href, form semantics, storage key와 roomId query navigation을 유지했다.
- single/multiplayer Canvas page와 runtime, Socket schema, server service와 gameplay rule은 변경하지 않았다.
- React state는 공개 playerId, nickname, public room DTO와 UI 표시 상태만 소유한다. token은 roomClient의 session/handshake 경계에 남는다.

## Lifecycle과 BFCache

- session ready/error/disconnected 구독마다 원본 callback을 감싸는 고유 wrapper를 Set에 넣고 disposer는 자기 wrapper만 idempotent하게 제거한다.
- ready replay는 캡처한 `activeSession` 객체가 현재 객체와 동일하고 wrapper가 Set에 남아 있을 때만 실행한다. 별도 session revision은 추가하지 않았다.
- lobby effect는 `onRoomUpdated`, `onRoomMessage`, `onRoomResult`, `onGlobalMessage`, `onChatResult`, `onSessionReady`, `onSessionError`, `onSessionDisconnected` disposer를 모두 정리한다.
- React lifecycle은 roomClient singleton의 connect/disconnect를 호출하지 않는다.
- pagehide는 구독과 sound만 정리하고 root를 unmount하지 않으며, pageshow persisted listener는 reload를 위해 유지한다.

## 관찰된 실패와 정정

- 첫 package install shell이 기본 Node 22를 사용해 engine warning을 냈다. 해당 환경을 검증 근거로 사용하지 않고 같은 exact install을 Node 24.18.0/npm 11.16.0에서 즉시 다시 실행했으며 lockfile의 무관한 platform metadata churn도 제거했다.
- 첫 Vite-dev lifecycle test는 초기 `room:sync`를 WebSocket frame에서만 찾았기 때문에 0건으로 실패했다. Socket.IO가 upgrade 전 polling POST로 보낸 요청을 함께 관찰하도록 test monitor만 수정했고 같은 gate가 통과했다.

## 남은 위험과 rollback

- WebKit/Firefox, 외부 TLS/reverse proxy, 실제 browser history 기반 BFCache eligibility와 장시간 soak는 실행하지 않았다.
- Fast Refresh와 React game page는 범위 밖이며 plugin을 추가하지 않았다.
- rollback은 최종 `docs: record Goal 5 migration` → `231b09d` → `45e016b` → `d6a7d6e` 순서로 revert한다. 전체 rollback은 기존 HTML inline module shell과 이전 package lock을 복원한다.
