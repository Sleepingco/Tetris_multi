# Goal 4 — Server TypeScript Build and Shared Core Output

## 목적과 기준

- 기준 main: `79042e87cb03dcf516ac3b6d66fd6a56688145a5`
- branch: `codex/add-server-typescript-build`
- 검증 대상 commit: `294033d`, `51a60aa`, `7d32c51`
- 목적: production TypeScript runtime loader 없이 실행되는 `dist/server`와 Vite hash에 의존하지 않는 shared core output을 만든다.

## 환경

- Node.js: `24.18.0`
- npm: `11.16.0`
- TypeScript: `7.0.2`
- Vite: `8.1.5`
- Zod: `4.4.3`
- 새 dependency와 lockfile 변경: 없음

## 변경과 의도된 기능 변화

- root CommonJS를 유지하고 emit 전용 NodeNext 설정과 Node 표준 라이브러리 build helper 하나를 추가했다.
- `src/client/package.json`의 ESM 경계를 output에 그대로 복사해 compiled dynamic import의 default export 의미를 보존했다.
- `src/app.ts`와 `socketSecurity.ts`만 대표 TypeScript runtime으로 전환했다. 전체 server 전환, protocol과 gameplay 변화는 없다.
- package main/start는 `dist/server/app.js`, development server는 server artifact build 후 같은 entry를 실행한다.
- compiled `__dirname` 기준으로 `dist/client` static root를 계산한다.
- source map은 생성하지 않으며 운영 오류는 compiled JavaScript 위치로 기록한다.

## Production dependency-only smoke

- 별도 임시 release에 `package.json`, lockfile과 미리 생성한 `dist`만 복사했다.
- `npm ci --omit=dev --ignore-scripts` 후 production dependency는 `express@5.2.1`, `socket.io@4.8.3`, `zod@4.4.3`만 확인했다.
- TypeScript, Vite와 Playwright가 없는 Node 24 환경에서 compiled server를 기동했다.
- `/`, 네 HTML, 대표 hashed JavaScript와 `/socket.io/socket.io.js`: HTTP 200
- `/server/app.js`와 대표 `.map`: HTTP 404
- compiled match/core/PVE service로 bundled V4 decision을 한 번 실행해 `policyUsed=placement_v4`, `fallbackReason=null`, fallback 0을 확인했다.

## 실패와 미실행 범위

- 첫 localhost 기동은 sandbox bind 제한과 기본 PATH의 Node 22를 확인하기 위한 실패였으며 application 판정에 사용하지 않았다. `.nvmrc`의 Node 24.18.0을 활성화하고 승인된 local bind에서 같은 compiled entry를 재실행해 통과했다.
- WebKit/Firefox, 외부 TLS/reverse proxy, container image와 장시간 soak는 실행하지 않았다.
- `dev:server`는 build-then-run만 제공하며 watch mode는 추가하지 않았다.

## 보안·데이터 영향

- server artifact는 browser static root 밖에 있고 HTTP로 노출되지 않는다.
- artifact test가 `.ts`, source map, `.env`, test/e2e/fixture 경로를 거부한다.
- token/session, room/match data schema와 저장 방식은 변경하지 않았다.

## 남은 위험과 rollback

- 기존 JavaScript server는 `allowJs`로 emit되며 전체 strict TypeScript 전환은 Goal 8 범위다.
- build helper가 복사하는 non-code runtime file은 client ESM manifest와 PVE model asset으로 제한된다.
- runtime entry commit을 revert하고 package start를 `node src/app.js`로 되돌린 뒤 build/output commit을 revert하면 기존 CommonJS source runtime으로 복귀한다.

## Merge Gate

- Goal 4 build/output, 대표 runtime 전환, 단일 artifact 검증과 문서만 local branch에 준비했다.
- push, main merge, branch 삭제와 Goal 5는 수행하지 않는다.
