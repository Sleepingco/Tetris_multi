## 변경과 불변조건

- Goal 문서는 `lines`를 display snapshot과 test 계약에는 포함하지만 visible single HUD에는 추가하지 않는다고 명확히 했다.
- display snapshot은 score, lines, hold piece, next 2개와 phase만 포함한다. board, active piece, tick, 전체 queue, callback과 Socket/session 정보는 포함하지 않는다.
- `src/client/game/runtime/displayBridge.js`는 현재 runtime 전용 cached store다. 같은 값은 같은 snapshot reference를 유지하고 실제 표시 값 변경만 독립 subscriber에게 알린다.
- `renderBlocks`, init, applySnapshot, appendServerBag와 server bag 고갈 종료 경계에서 cache를 비교한다. 비동기 line clear는 `lineClearing`과 최종 `playing`을 각각 한 번 알린다.
- `tetrisSingle.html`은 기존 head, theme pre-paint, CSS와 URL을 유지하고 body만 `tetrisSingle.tsx` StrictMode root로 옮겼다.
- single runtime에는 `boardCanvasEl`만 전달한다. score, hold, next와 game-over는 page-local `SingleHud`/`PiecePreview`가 렌더링하며 기존 multiplayer DOM adapter는 변경하지 않는다.
- Canvas ID/크기, keyboard, theme/sound storage, CSS class와 selector를 보존했다. restart는 현재 runtime `init()`을 재사용한다.
- pagehide는 runtime keyboard/timer/animation과 sound cleanup을 수행하고 pageshow persisted listener는 reload까지 유지한다.

## Lifecycle, DOM과 artifact 확인

- 일반 이동은 display 알림 0회, hold/hard drop은 최종 표시 1회, line clear는 진입/완료 2회, applySnapshot은 1회이며 init은 중복 없이 최종 상태만 알린다.
- 같은 callback을 중복 등록해도 disposer가 자기 wrapper만 제거한다. unsubscribe/destroy는 idempotent하고 destroy 이후 publish는 무시한다.
- StrictMode setup-cleanup-setup 뒤 keyboard와 sound listener는 한 세트다. 반복 game-over/restart 후 입력 한 번은 Canvas를 한 칸만 이동한다.
- next는 `.next-slot` 2개와 `.next-cell` 32개, hold는 16개 cell 및 piece/`.preview` class를 유지한다.
- synthetic `pagehide → pageshow.persisted → reload` 뒤 입력 lifecycle을 복원하고 browser console error와 pageerror는 0개였다.
- production에서 `/pages/tetrisSingle.tsx`와 built single entry `.map`은 HTTP 404다. artifact test는 `.ts`, `.tsx`, declaration과 `.map` 배포를 계속 차단한다.

## 관찰된 실패와 정정

- sandbox 안 첫 single Playwright는 localhost bind `EPERM`으로 시작하지 못했다. application 실패로 판단하지 않고 같은 명령을 허용된 local 실행으로 재실행해 통과했다.
- 첫 Vite-dev gate는 hold 뒤 다른 piece 색으로 이동을 읽은 test 순서와 restart 뒤 key 없는 portal의 score text 소유권 문제를 각각 드러냈다. 이동 검증을 hold 전에 배치하고 portal key 및 score 문자열을 고정한 뒤 전체 Vite-dev와 production gate를 다시 통과했다.

## 보안·성능과 남은 위험

- display snapshot과 React state/props/DOM에는 token, socketId와 callback이 없다. board와 전체 queue도 매 frame 복사하지 않는다.
- gameplay rule, score/line 계산, Socket.IO protocol, multiplayer/PVE runtime과 server는 변경하지 않았다.
- 실제 browser history 기반 BFCache eligibility, WebKit/Firefox, 외부 TLS/reverse proxy와 장시간 timer/animation soak는 실행하지 않았다.

## Rollback과 merge gate

- 전체 rollback은 최종 docs commit → `8e0aa3e` → `48fe1af` → `06a0565` → `2b25e1e` 순서로 revert한다.
- React/test commit만 되돌리면 기존 inline single entry로 복귀하고, additive display bridge와 문서도 이어서 revert하면 기준 main과 동일해진다.
- Goal 6 변경과 검증은 local branch에만 준비했다. push, PR, main merge, branch 삭제, change-log main 통합 기록과 Goal 7은 수행하지 않는다.
