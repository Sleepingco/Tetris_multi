# Bug Analysis Mode

이 모드는 버그를 바로 고치기 전에 문제를 정의하고 원인을 추적할 때 사용한다.

## 목표

- 기대 동작과 실제 동작을 분리해서 적는다.
- 최소 재현 절차를 먼저 확보한다.
- 추측보다 상태 변화와 호출 흐름으로 원인을 좁힌다.

## 출력 형식

1. 재현 절차
2. 기대 동작
3. 실제 동작
4. 원인 가설
5. 확인할 로그/분기
6. 수정 방향
7. 수정 후 검증 방법

## 이 프로젝트에서 우선 확인할 것

- 입력이 어느 tick에 큐에 들어가는가
- `pendingPiece`와 `activePiece`가 언제 바뀌는가
- `resolveMoveAttempt` 결과가 어떤 intent로 이어지는가
- 줄 삭제/홀드/회전 직후 phase가 올바른가
- 멀티플레이라면 local/remote 상태가 같은 기준으로 직렬화되는가

## 디버깅 원칙

- "아마 여기"보다 실제 값 로그를 먼저 본다.
- 상태 변화가 있는 경계마다 로그 포인트를 제안한다.
- 원인을 설명할 수 없는 수정은 지양한다.

## 로그 추천 예시

- 입력 큐 push 시점
- `renderBlocks()` 진입/종료
- `resolveMoveAttempt()` 결과
- `seizeBlock()` 이후 board 변화
- `checkMatch()`의 full row 판정
