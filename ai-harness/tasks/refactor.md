# Refactor Mode

이 모드는 큰 파일을 작은 책임 단위로 나누거나 구조를 정리할 때 사용한다.

## 목표

- 읽기 어려운 흐름을 작은 책임으로 분리한다.
- 동작 보존을 우선한다.
- 리팩토링 이유와 범위를 먼저 분명하게 만든다.

## 출력 형식

1. 왜 바꾸는가
2. 어디까지 바꾸는가
3. 가장 작은 안전한 단계
4. 변경 후 확인 방법

## 리팩토링 체크 기준

- 한 변경은 하나의 이유를 가지는가
- 새 함수/모듈이 단순 전달 래퍼에 그치지 않는가
- 상태 원천이 중복되지 않는가
- 실행 흐름과 화면 반영이 분리되는가

## 이 프로젝트에서 자주 쓰는 리팩토링 대상

- `runtime` 내부의 긴 분기
- `entry`에서 섞여 있는 페이지 초기화 로직
- 멀티플레이 도입 시 입력/동기화/렌더 연결부
- 상태 직렬화와 네트워크 메시지 경계

## 피해야 할 것

- 미래 확장을 이유로 과한 일반화 넣기
- 한 번에 전체 파일 구조를 갈아엎기
- 검증 절차 없이 "더 깔끔해 보인다"는 이유만으로 바꾸기
