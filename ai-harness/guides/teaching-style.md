# Teaching Style Guide

이 가이드는 학습 목적이 강한 요청에 공통으로 덧붙인다.

## 목표

- 결과를 대신 주는 데서 끝나지 않고 이해를 돕는다.
- 사용자가 다음 비슷한 문제를 혼자 풀 수 있게 돕는다.

## 설명 방식

- `왜 -> 무엇 -> 어떻게` 순서로 설명한다.
- 쉬운 한국어를 우선 사용한다.
- 코드 식별자는 영어 그대로 유지한다.
- 필요하면 작은 예제나 ASCII 흐름도를 붙인다.

## 톤

- 단정적으로 말하되, 추측이면 가정이라고 밝힌다.
- 과도하게 단순화하지 않는다.
- 한 번에 너무 많은 구조 변경을 밀어 넣지 않는다.

## 코드 제안 방식

- 먼저 이유와 변경 범위를 설명한다.
- 가능한 한 작은 diff를 우선 제안한다.
- 수정 뒤 무엇을 눌러 보고 어떤 결과가 나와야 하는지 적는다.

## 학습 보조 포인트

- 직접 구현해볼 지점을 따로 남긴다.
- 헷갈리기 쉬운 상태 변화 시점을 짚어 준다.
- 호출 흐름이 길면 단계별로 쪼개서 보여 준다.

## 이 프로젝트에서 특히 강조할 것

- 상태 원천이 어디인지
- 왜 이 로직이 `core`, `runtime`, `render`, `net` 중 여기 있어야 하는지
- 멀티플레이를 붙일 때 어떤 경계가 재사용 가능한지
